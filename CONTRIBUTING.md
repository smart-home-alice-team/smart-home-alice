# Правила совместной работы

## Ветки
- `main` — стабильные релизы, прямые коммиты запрещены (branch protection).
- `develop` — интеграционная ветка, в неё попадают только Pull Request.
- `feature/<код-WBS>-<кратко>` — задачи, например `feature/A12-oauth`, `feature/A20-matter`.
- `fix/<номер-issue>-<кратко>` — исправление дефектов.

## Коммиты
Формат: `<тип>(<модуль>): <описание> (#<issue>)`, типы: `feat`, `fix`, `test`, `docs`, `ci`, `refactor`.
Пример: `feat(cloud): метод /v1.0/user/devices/query (#14)`.

## Pull Request
1. Связать PR с задачей трекера (`Closes #14`).
2. CI (линтер + тесты) должен быть зелёным.
3. Минимум одно одобрение ревьюера: облако — ревьюер Алексей, шлюз — ревьюер Илья, документация — Карина.
4. Слияние в `develop` — squash merge; в `main` — по итогам итерации (merge commit + тег версии).

## Роли и права в репозитории
| Участник | Роль GitHub | Зона ответственности |
|---|---|---|
| Карина | Admin | настройки, трекер, документация, тесты |
| Илья | Maintain | `cloud/`, ревью `gateway/` |
| Алексей | Maintain | `gateway/`, `infra/`, CI, ревью `cloud/` |

## Задачи
Статусы доски: Backlog → To Do → In Progress → Review → Done. Поля: исполнитель, приоритет (MoSCoW), итерация, оценка (дни), код WBS.
